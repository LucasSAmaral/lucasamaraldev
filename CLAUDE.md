# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal portfolio site for Lucas Amaral, built with Next.js 16 (App Router) and React 19. Content and UI copy are largely in Portuguese; code identifiers and comments are in English/Portuguese mixed as found in the file.

## Commands

```bash
npm run dev       # regenerates generated-config.json, then starts Next.js dev server (--turbopack)
npm run build     # regenerates generated-config.json, then builds for production
npm start         # runs the production build
npm run lint      # next lint (config: next/core-web-vitals)
npm run config    # regenerates generated-config.json only (ts-node src/config/build-config.ts)
npm run release   # cuts a release with release-it (bumps version, updates CHANGELOG.md, tags)
```

Node version is pinned via `.nvmrc` (22) and the Dockerfile (`node:22.22-alpine`).

### Tests (Cypress only — no Jest/unit test runner)

- Component tests live next to the components under `tests/` folders as `*.component.cy.tsx` (e.g. `src/app/work-experience/components/tests/DeskCard.component.cy.tsx`).
- E2E tests live in `cypress/e2e/*.cy.ts` and run against a built/served app (`baseUrl: http://localhost:3000`).

```bash
npx cypress open                              # interactive runner (component or e2e)
npx cypress run --component                   # all component tests, headless
npx cypress run --component --spec "src/app/work-experience/components/tests/DeskCard.component.cy.tsx"
npx cypress run --e2e                          # all e2e tests, headless (requires app running/build+start)
npx cypress run --e2e --spec "cypress/e2e/contact-form.cy.ts"
```

CI (`.github/workflows/cypress.yml`, `ci-cd.yml`) always runs `npm run build && npm start` before Cypress, then component specs, then e2e specs.

**`data-cy` attributes**: use the custom `cy.getDataCy('some-id')` command (defined in `cypress/support/commands.ts`) instead of raw `cy.get('[data-cy=...]')` when writing new specs.

## Configuration: the generated-config build step

There is no `.env`-driven runtime config; content and app config are assembled at build/dev time:

- `src/config/build-config.ts` reads `navigation-menu-config.json`, `app-config.json`, `locale/common-locale.json`, `locale/pt.json`, `locale/en.json`, deep-merges them (`merge-options`, later files win), and writes the result to `generated-config.json` at the repo root.
- `generated-config.json` is gitignored and regenerated by `npm run config` (also runs automatically before `dev`/`build`) — **do not hand-edit it**; edit the source JSON files under `src/config/` instead.
- App code imports `generated-config.json` directly (e.g. `src/app/contact/actions.ts` imports `CONFIG` from `../../../generated-config.json`). If this file is missing, run `npm run config` first.
- Secrets used for the contact form's EmailJS integration (`SERVICE_ID`, `TEMPLATE_ID`, `USER_ID`) live in `.env` and are read via `process.env` in `src/app/contact/actions.ts`; the actual EmailJS API URL comes from `app-config.json` instead of the env file.

## i18n

There is no i18n library. `pt.json` / `en.json` under `src/config/locale/` are merged into `generated-config.json` under `locale.pt` / `locale.en`, and components read the string for the currently selected language directly from that object based on `LanguageOptionsContext`'s `selectedLanguage` (`'pt' | 'en'`, defaulting to `'pt'`, overridable via the `?lang=` search param — see `src/app/components/language-options/LanguageOptions.context.tsx`). When adding user-facing copy, add the key to **both** `pt.json` and `en.json` under the same path, and consume it from `generated-config.json`.

## Architecture

- **App Router** under `src/app/`; one folder per route (`about-me/`, `work-experience/`, `contact/`) each with its own `page.tsx` and a local `components/` folder for route-specific components.
- **Shared UI** lives in `src/app/components/`. Cross-cutting concerns are implemented as React Context providers, each colocated as a `<Feature>.context.tsx` next to its `<Feature>.component.tsx`:
  - `modal/Modal.context.tsx` + `Modal.container.tsx` — global modal, driven by a state machine (`CLOSED → OPENING → OPENED → CLOSING → CLOSED`) rendered into `#modal` (see `layout.tsx`). Open modals via the `useModal()` hook, not by rendering modal components directly.
  - `navigation-menu/NavigationMenu.context.tsx` — nav menu open/close state (`MenuStatus`), reused by both the navigation menu and the language switcher.
  - `language-options/LanguageOptions.context.tsx` — current language, described above.
  - All providers are composed in `src/app/Providers.tsx` (`QueryClientProvider > Suspense > LanguageOptionsProvider > ModalProvider > NavigationMenuProvider`); add new global providers there, innermost-last.
- **Styling** is `styled-components` with SSR support via `src/app/lib/registry.tsx` (`StyledComponentsRegistry`, wraps the app in `layout.tsx`). Global styles are in `src/app/styles/globalStyle.ts`; shared style primitives/tokens are in `src/app/components/commons/styles.ts`.
- **File naming convention** (follow this for new files): `Name.component.tsx` (component), `Name.context.tsx` (context/provider), `Name.container.tsx` (container wiring context to render output), plain `helpers.ts`/`actions.ts` for logic. Cypress component specs mirror the component name: `Name.component.cy.tsx` in a sibling `tests/` folder.
- **Server actions**: `'use server'` functions (e.g. `src/app/contact/actions.ts`) are used for backend calls (EmailJS submission) instead of API routes.
- Path alias `@/*` maps to `src/*` (see `tsconfig.json`).

## Formatting

Prettier is configured (`.prettierrc`): single quotes, semicolons, trailing commas, 100 char width, `arrowParens: avoid`. Match this style; there's no separate format script wired up, so rely on editor integration or `npx prettier --write`.

## Releasing

Version bumps, tagging, and `CHANGELOG.md` are managed by `release-it` (`npm run release`) using Conventional Commits. Commit messages follow `type: descrição em português` (e.g. `feat:`, `fix:`, `chore:`, `test:`), and pushing a tag triggers `.github/workflows/ci-cd.yml` (Cypress component + e2e → Docker image build/push to `lucassamaral/lucasamaraldev` → Vercel production deploy).
